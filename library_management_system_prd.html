Executive Summary

The Library Management System (LMS) is a web-based application designed to digitise and streamline the operation of an academic institution's library. The platform replaces manual, paper-based processes with a secure, role-driven digital workflow that covers the complete lifecycle of book issuance and return.

The system serves two distinct user roles — Administrators and Students — each with a tailored interface and strictly enforced permission boundary. Administrators control the entire inventory and transaction workflow; students register and may view their own borrowing history.

The technical foundation is a modern, async Python backend (FastAPI + Motor/MongoDB) paired with a React single-page application built on Vite. All communication is stateless and secured via JSON Web Tokens, with passwords hashed using bcrypt via passlib.

Scope

This PRD covers the first production release (v1.0). Features such as email notifications, reservation queues, barcode scanning, and mobile apps are scoped to future iterations.

User Stories

AdminUS-01

As an admin, I can log in with my email and password so that I can access the management dashboard securely.

StudentUS-02

As a student, I can register with my name, email, password, phone, course, and year so that a library account is created automatically.

StudentUS-03

As a student, I receive a unique studentId upon registration so that admins can identify me quickly.

AdminUS-04

As an admin, I can search for a student by their studentId so that I can verify their identity before issuing a book.

AdminUS-05

As an admin, I can issue a book to a student, reducing available copies and recording the transaction with a 7-day due date.

AdminUS-06

As an admin, I can mark a book as returned, triggering automatic fine calculation (₹5/day overdue) and restoring stock.

AdminUS-07

As an admin, I can add, edit, and delete books in the catalogue so that the inventory stays current.

AdminUS-08

As an admin, I can view a dashboard showing total books, issued books, overdue count, student count, and accrued fines.

SystemUS-09

The system prevents issuing a book when availableCopies is 0, returning a meaningful error to the admin.

SystemUS-10

The system rejects any request without a valid JWT or with a role mismatch, returning HTTP 401/403.

API Specification

Base URL

All endpoints are prefixed with /api. The server runs on http://localhost:8000 by default. All responses are JSON. All datetimes are ISO 8601 UTC.

Authentication — /api/auth

POST
/api/auth/register
Register a new student account. Auto-generates studentId. Returns 201 with user object (no password). Never accepts role: "admin".
POST
/api/auth/login
Login for admin or student. Returns { "access_token": "...", "token_type": "bearer", "role": "..." }. 401 on invalid credentials.

Books — /api/books  Admin Only

GET
/api/books
List all books. Supports ?title= and ?author= query params for case-insensitive partial search (MongoDB $regex).
POST
/api/books
Create a new book. availableCopies is set equal to totalCopies on creation. Returns 201.
PUT
/api/books/{id}
Update book metadata or copy counts. Validate that availableCopies ≤ totalCopies after update.
DELETE
/api/books/{id}
Soft-delete or hard-delete a book. Return 409 Conflict if active transactions exist.

Students — /api/students  Admin Only

GET
/api/students
List all active students (role = "student"). Passwords excluded from response.
GET
/api/students/search/{studentId}
Look up a student by their studentId string (e.g. "STU-0042"). Used in the Issue Book flow.
PUT
/api/students/{id}
Update student profile fields (name, phone, course, year, active). Email and role are immutable after creation.
DELETE
/api/students/{id}
Soft-delete (set active: false). Return 409 if student has unreturned books.

Transactions — /api/transactions  Admin Only

POST
/api/transactions/issue
Issue a book. Body: { studentId, bookId }. Validates student is active, book has availableCopies > 0, and student has no more than 3 active issues (configurable). Atomically decrements stock and creates transaction.
POST
/api/transactions/return
Process return. Body: { transactionId }. Sets returnDate, calculates fine, increments availableCopies, sets status: "RETURNED". Returns fine amount in response.
GET
/api/transactions
List all transactions with joined student name, book title. Supports ?status=ISSUED filter. Paginated (?page=1&limit=20).

Dashboard — /api/dashboard  Admin Only

GET
/api/dashboard/stats
Single aggregated response via MongoDB aggregation pipeline. Returns: totalBooks, totalStudents, issuedBooks, overdueBooks, totalFine.

Authentication System

JWT Token Structure

# Header { "alg": "HS256", "typ": "JWT" } # Payload { "sub": "<user_id_string>", # MongoDB ObjectId as str "role": "admin", # or "student" "exp": 1719000000 # Unix timestamp, 24h default } # Signed with: SECRET_KEY from .env (min 32 chars, random)

FastAPI Dependencies

async def get_current_user(token: str = Depends(oauth2_scheme)): # 1. Decode JWT → payload # 2. Fetch user from DB by payload["sub"] # 3. Return user doc or raise HTTP 401 ... async def admin_only(user = Depends(get_current_user)): if user["role"] != "admin": raise HTTPException(status_code=403, detail="Admin access required") return user

Password Hashing

from passlib.context import CryptContext pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto") def hash_password(plain: str) -> str: return pwd_context.hash(plain) def verify_password(plain: str, hashed: str) -> bool: return pwd_context.verify(plain, hashed)

Frontend JWT Storage & Injection

// services/api.js import axios from "axios"; const api = axios.create({ baseURL: "http://localhost:8000/api" }); api.interceptors.request.use(config => { const token = localStorage.getItem("lms_token"); if (token) config.headers.Authorization = `Bearer ${token}`; return config; }); api.interceptors.response.use( res => res, err => { if (err.response?.status === 401) { localStorage.clear(); window.location.href = "/login"; } return Promise.reject(err); } ); export default api;

Business Logic

Student ID Generation

On registration, the backend queries the users collection for the count of existing students, then formats: STU-{count+1:04d} (e.g. "STU-0001", "STU-0042"). A unique index on studentId ensures race conditions are caught by MongoDB.

Issue Validation Rules

CheckFailure Response
Student exists and active: true404 / 409 — "Student account is inactive"
availableCopies > 0409 — "No copies available"
Student has fewer than 3 active issues409 — "Borrow limit reached"
Student does not already have this book issued409 — "Book already issued to student"

Fine Calculation

# On return days_late = max(0, (return_date - due_date).days) fine = days_late * 5 # ₹5 per day overdue # fine is stored on the transaction record # fine of 0 means returned on time or early

Dashboard Aggregation

# Single MongoDB aggregation pipeline [ { "$facet": { "totalBooks": [{ "$count": "n" }], # books collection "totalStudents": [ # users collection { "$match": { "role": "student", "active": True } }, { "$count": "n" } ], "issuedBooks": [ # transactions collection { "$match": { "status": "ISSUED" } }, { "$count": "n" } ], "overdueBooks": [ { "$match": { "status": "ISSUED", "dueDate": { "$lt": "$$NOW" } } }, { "$count": "n" } ], "totalFine": [ { "$group": { "_id": null, "sum": { "$sum": "$fine" } } } ] }} ]

Risks & Mitigations

RiskSeverityLikelihoodMitigation
Race condition on book issue (two admins issue last copy simultaneously)HighLowUse MongoDB findOneAndUpdate with $inc and a condition check; return error if result is null
JWT secret leakage via committed .envHighLowAdd .env to .gitignore; rotate key in production; document in README
studentId collision under high registration loadMediumLowUnique index on studentId; retry with incremented counter on duplicate key error
MongoDB connection pool exhaustionMediumMediumMotor manages pool; tune maxPoolSize in connection string for production
Stale availableCopies in frontend cacheLowMediumAlways fetch fresh data before issue flow; no client-side caching of stock counts
